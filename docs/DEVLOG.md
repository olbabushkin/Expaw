# Devlog: история разработки Telegram Intent Monitor

Хроника первой сессии разработки (02.07.2026): что построено, какие решения
приняты и почему, на какие грабли наступили. Дополняет README — тот описывает
«как пользоваться», этот документ — «как мы сюда пришли».

## Что это

Система мониторинга Telegram-чатов: юзербот слушает чаты владельца, worker
классифицирует сообщения по интентам (двухступенчато: префильтр → Claude
Haiku), совпадения публикуются в форум-группу — один топик = один интент.
Реакции 👍/👎 на посты копятся как разметка и используются для автоматического
улучшения промптов с бэктестом.

## Архитектура и ключевые решения

```
[Чаты владельца] ─push MTProto→ [userbot: Telethon] → PostgreSQL ← [worker: префильтр+LLM]
                                                          ↑  ↓ publish
[Админ] ─команды→ [bot: aiogram 3] ──────────────────────┘  [форум-группа: топики]
                                                              ↑ реакции 👍/👎 = разметка
```

Решения, зафиксированные с самого начала (из исходного плана):

1. **Push через MTProto**, поллинг — только редкая страховочная сверка (раз в
   2 ч, `min_id` от последнего сохранённого сообщения).
2. **Postgres как очередь** (`FOR UPDATE SKIP LOCKED`) — без Redis/Celery;
   worker масштабируется экземплярами.
3. **Бот и юзербот общаются только через БД** (статусы-задачи) — никакого IPC.
4. **Двухступенчатая классификация**: бесплатный префильтр по ключевым
   словам/regex → LLM только для кандидатов. Главный контроль стоимости.
5. **LLM — `claude-haiku-4-5`** со structured outputs
   (`output_config.format`, json_schema): бинарная классификация, дорогая
   модель не нужна; JSON гарантированно валиден (если не обрезан — см. грабли).
6. Один docker-образ, три сервиса с разными командами + сервис `migrate`
   (идемпотентный раннер SQL-файлов, `schema_migrations`).

Решения, изменённые по ходу сессии:

7. **Юзербот = основной аккаунт владельца** (для ~10 чатов риск бана
   минимален). Следствие: система **сама никуда не вступает и не выходит** —
   `/add_chat` только регистрирует чат, менеджер пула раз в ~5 мин проверяет
   членство (`GetParticipantRequest` / `CheckChatInviteRequest`) и включает
   мониторинг, когда владелец вступил сам. `/remove_chat` только выключает
   отслеживание. Изначальные лимиты join (8/сутки, паузы 5–15 мин) удалены
   за ненадобностью.
8. **Один интент на сообщение**: модель просят выбрать лучший, код страхует
   выбором максимального score при нескольких match.
9. **Бэкфилл истории**: при включении мониторинга подгружается история за
   `BACKFILL_DAYS` (30) дней, кап `BACKFILL_MAX_MESSAGES` (3000). Точка
   отсчёта сверки фиксируется, чтобы она не утянула лишнюю историю.
10. **Хостинг**: начали с локальной машины (Mac, Docker Desktop). CI/CD на
    GitHub Actions (rsync+ssh на VPS) написан и ждёт переезда; Render
    рассмотрен и отклонён (дороже VPS в 3–6 раз, эфемерная FS требует
    StringSession).

## Контур самообучения (главная фича)

- Посты в топиках размечаются реакциями: 👍 = верно, 👎 = ложное срабатывание.
  Ловит `router.message_reaction()` (бот должен быть админом группы).
- Разметка живёт в таблице `feedback` с привязкой к **сообщению** (не к
  match!) — переживает пересчёты, выборка накапливается между итерациями.
- **Каждые 5 новых реакций по интенту — автотюнинг** (маркер в `kv` против
  повторов): LLM переписывает критерии по ложным/подтверждённым примерам.
- **Бэктест перед применением**: новая версия критериев прогоняется по всем
  размеченным сообщениям. Старую версию гонять не нужно — всё размеченное ею
  матчилось, её точность = доля лайков. Отчёт: сохранённые 👍, отсеянные 👎,
  точность до → после. **Применяется только если не потерян ни один лайк**,
  иначе критерии не трогаются и админ получает отчёт.
- Префильтр при тюнинге **только расширяется** (union со старым) — покрытие
  не сужается, «не пропускать» важнее точности дешёвого фильтра. Плюс
  контроль: каждое лайкнутое сообщение обязано проходить префильтр, иначе
  предупреждение.
- `/recalc confirm` — полный пересчёт: удалить посты бота из топиков,
  очистить matches и антидубль-хэши, вернуть все сообщения в статус `new`.
  Автотюнинг сам `/recalc` не запускает — решение за админом.

Рабочий цикл: разметка → (авто)тюнинг с бэктестом → `/recalc` → разметка.

## Прочие фичи

- `/add_intent` создаёт топик в форуме; `/set_prompt` автоматически подбирает
  префильтр через LLM (если пуст); `/suggest_prefilter` — перегенерация.
- `/remove_intent code confirm` — интент + топик + его данные.
- `/purge_chat` — чат со всеми сообщениями/совпадениями/фидбеком (для
  активного сначала `/remove_chat`).
- Антидубль двух уровней: UNIQUE(message, intent) + хэш нормализованного
  текста в окне 48 ч (хэш пишется только после успешной отправки — иначе
  неудачная публикация делала собственный ретрай «дублем»).
- Посты: обрезка до 1000 символов, ссылка на оригинал
  (`t.me/c/<id>/<msg>` для приватных), источник, автор, **возраст оригинала**
  («50 мин назад» / «5 дн назад») и score.
- Топик «Система»: события старта, join/ошибки, FloodWait, отчёты
  автотюнинга; watchdog по heartbeat (алерт при молчании сервиса >10 мин);
  ретеншн `skipped` через 14 дней.

## Грабли сессии (чтобы не наступать повторно)

| Симптом | Причина | Решение |
|---|---|---|
| `migrate` падает connection refused на первом `up` | pg_isready отвечал «healthy» временному init-серверу postgres (unix-сокет), migrate стучался в момент рестарта | healthcheck с `-h 127.0.0.1` + `start_period` + ретраи подключения в migrate.py |
| Бот молчит на `/start` | следствие предыдущего: bot/worker/userbot не стартовали (ждут migrate) | тот же фикс; повторный `docker compose up -d` |
| `not enough rights to create a topic` | бот не админ / без права Manage Topics; отдельная ловушка — два чата с одинаковым названием, бот добавлен не в тот | выдать право; сверять chat_id, не название |
| `'ascii' codec can't encode characters in position 8-107` при вызове Claude | в `.env` ключ `ANTHROPIC_API_KEY` скопировался с не-ASCII символами (автозамена при копировании через мессенджер); httpx требует ASCII в заголовках | перебить строку ключа плоским текстом; диагностика: `repr(os.environ[...])` внутри контейнера |
| `JSONDecodeError` в автотюнинге | ответ LLM обрезался по `max_tokens=500`, structured outputs гарантирует JSON только у дописанного ответа | max_tokens → 2000 везде + явная проверка `stop_reason == "max_tokens"` |
| `pip install` на Mac: `externally-managed-environment` | PEP 668 у Homebrew-питона | venv: `python3 -m venv .venv && source .venv/bin/activate` |
| pyaes не собирается в песочнице CI | баг системного setuptools (install_layout) — специфика окружения, в python:3.12-slim собирается | не воспроизводится в проде; локально — venv |
| `the input device is not a TTY` | heredoc в `docker compose exec` без `-T` | `docker compose exec -T ...` |
| Не приходит код логина Telethon | для живого аккаунта код приходит НЕ по СМС, а в чат «Telegram» на залогиненных устройствах (`SentCodeTypeApp`); чат бывает в архиве | диагностика: `send_code_request()` и смотреть тип; для нового номера сначала регистрация в официальном приложении |
| Реакции не приходят боту | нужен админ в группе + `message_reaction` в allowed_updates (aiogram включает сам при наличии хендлера) | не снимать админку с бота |

## Эксплуатационные заметки

- **Session-файл юзербота = полный доступ к аккаунту.** Вне git, права 600,
  volume `./data/session:/session`. Аварийная кнопка: Настройки → Устройства →
  завершить сессию. Смена аккаунта: стоп userbot → удалить session → 
  `python -m userbot.login` с новым номером (api_id/api_hash те же — это
  ключи приложения) → новый аккаунт должен состоять в отслеживаемых чатах.
- **Секреты**: всё в `.env` (в .gitignore). В ходе сессии токен бота и ключ
  Anthropic светились в переписке — рекомендована ротация (BotFather
  `/revoke`, console.anthropic.com → revoke key).
- **Стоимость**: контролируется префильтром; метрика «% дошедших до LLM» в
  `/stats`. Кап префильтра — 50 шаблонов; если LLM надобавлял мусора при
  тюнинге, чистить `/set_prefilter` руками.
- **Локальный режим**: мониторинг живёт, пока Mac не спит; после пробуждения
  `catch_up` + сверка добирают пропущенное. Данные в `./data/`.
- **Переезд на VPS**: `deploy/setup-server.sh` (Docker, rsync, юзер deploy,
  ключ для Actions) + секреты SSH_HOST/SSH_USER/SSH_KEY в GitHub + перенести
  `.env` и `data/session/`. Workflow `.github/workflows/deploy.yml`
  триггерится по push в `main` (ветка разработки — 
  `claude/telegram-intent-monitor-utcebn`, для активации CI/CD нужен merge).
